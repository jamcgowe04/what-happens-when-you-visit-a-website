## What this is

**What happens when you visit a website?** is an interactive web project that explains what happens behind the scenes when someone enters a URL and visits a website.

The project guides users through a journey from entering a website address to seeing the webpage appear in their browser. It breaks the process into eight steps:

1. ENtering the URL
2. Finding the Server
3. Establising a Connection
4. Sending the Request
5. Server Processing
6. Receiving the Response
7. Building the Webpage
8. The Website Appears

Users can move forward and backward through the journey, view a visual representation of browser-to-server communication, and click on technical terms to learn more about concepts such as DNS, IP addresses, HTTP, HTTPS, HTML, CSS, and JavaScript.

## Why does it exist?

The purpose of this project is to make the prcoess of visting a website understandable for people who may be curious about the process but may not have a technical background.

Visitng a website is almost instant in entering an address and reaching the website you want to visit, but many different processes happen between entering a URL and seeing the webpage. this project breaks those processes down into a smaller, understnable steps and presents them through an interactive experience rather than relying only on text.

The goal is to help students, beginning web developers, and anyone interested in how the web works develop a basic understanding of what happens behind visiting a website.

## What chnaged from Project 01 to Project 02?

Project 02 focused on improving the foundational experience from Project 02 based on evaluation and testing. The main goal was to make the project more interactive, educational, viusally engaging, and polished.

### Added URL validation and user feedback

Project 02 added URL Validation so the users receive feedback when they enter an empty ir invalid website address. The project also accepts common URLs without requiring to manually enter https://.

### Expanded educational content

The explanations for each stage were expanded to provide more context about what is happening during the website-request process.

### Added a browser-to-server visual

Project 01 was primarily text-based. project 02 added a visual representation shwoing the relationship between the **Browser**, **DNS**, **Web Server**.

The visual changes as the user progresses through the journey, providing another way to understand the communcation taking place behind the scenes.

### Added interactive technical definitons

clickable definitions were added for important technical terms

The definitions remain hidden until a user clicks on a term, keeping the interface uncluttered while allowing users to explore concepts when they want addtional information.

### Improved the concluding step
The Journey Complete screen was expanded to summarize and review what the user explored throughout the experience. Instead of simply ending after the final stage, the project now reinforces the major concepts covered during the journey.

### Improved visual design and transitions

For project 02, additional visual polish, stronger stage hierarchy, improved button styling, enhanced network visuals, URL presentation, and smoother stage transitions were integrated.

These changes were intended to make the experience feel more cohesive and give users clearer visual feedback as they moved through the journey.

### Improved responsive and accessibility considerations

The project was tested across desktop, tablet, and mobile screen sizes. The layout was adjusted to prevent content from overflowing and to keep the interactive elements usable on smaller screens.


### Removed or avoided unnecessary features

This web project was not intended to expand into a full real-time network diagnostic tool, account system, or database. These features were outside the scope of the educational experience and would have added complexity without directly supporting the project's primary goal.
